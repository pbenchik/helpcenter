# Send event

Send event позволяет отправить событие в трекер.

<div data-with-frame="true"><figure><img src="../../../../.gitbook/assets/Frame 2248 (67).png" alt=""><figcaption></figcaption></figure></div>

### How it works

Шаг используется для:

* передачи событий по пользователю
* отслеживания конверсий по кампаниям
* фиксации действий пользователя
* аналитики и отслеживания конверсий

<div data-with-frame="true"><figure><img src="../../../../.gitbook/assets/Frame 2248 (68).png" alt=""><figcaption></figcaption></figure></div>

Событие отправляется в трекер и автоматически привязывается к пользователю.

* если пользователь пришёл по рекламной кампании, событие фиксируется в соответствующей кампании
* если пользователь органический, событие отобразится в органической кампании
* передача происходит по `clickid`
* событие фиксируется в аналитике сразу после выполнения шага

### Settings

Базовые настройки шага.

<div data-with-frame="true"><figure><img src="../../../../.gitbook/assets/Frame 2248 (70).png" alt=""><figcaption></figcaption></figure></div>

* **Title** — название шага. Используется для удобной навигации внутри flow
* **Delay** — задержка перед выполнением шага. Во время задержки сообщения пользователя игнорируются, а действие не выполняется
* **Finish Status** — статус диалога после выполнения шага:
  * `nothing` — переход к следующему шагу
  * `auto` — автоматическое продолжение диалога
  * `waiting` — ожидание ответа пользователя
  * `manual` — перевод в ручной режим
  * `blocked` — блокировка диалога
  * `finished` — завершение диалога
* **Hide keyboard** — скрывает клавиатуру из предыдущего шага
* **Is start step of flow** — отмечает шаг как стартовый
* **Skip the transition to next step** — отключает автоматический переход на следующий шаг. Используется в связке со статусом `waiting`

Если **Skip the transition to next step** включён:

* шаг не переключится автоматически
* система останется на текущем шаге
* будет ожидать ответ пользователя

### Event

Здесь выбирается событие, которое будет отправлено в трекер.

<div data-with-frame="true"><figure><img src="../../../../.gitbook/assets/Frame 2248 (69).png" alt=""><figcaption></figcaption></figure></div>

**Event type** — выбор типа события из списка:

* **Subscribe** — подписка пользователя
* **Registration** — регистрация пользователя
* **Deposit (sale)** — депозит пользователя
* **Redeposit (resale)** — повторный депозит

### Steps / Instructions

1. Добавьте шаг **Send event** в flow.
2. Откройте блок **Event**.
3. Выберите нужный **Event type**.
4. При необходимости настройте параметры в блоке **Settings**.
5. Подключите следующий шаг.

### Examples

* **Сценарий 1** — `Send event → Registration`\
  Событие регистрации отправится в трекер.
* **Сценарий 2** — `Send event → Deposit`\
  Событие депозита отправится в трекер.

### Notes

* Используйте шаг, когда нужно передать событие в трекер
* Шаг подходит для фиксации действий пользователя
* Шаг помогает строить аналитику и отслеживать конверсии
